# 05 — Digital KSP Operating Model

## 1. Goal

Kurikulum Satuan Pendidikan tidak lagi berupa file Word yang berdiri sendiri. Ia menjadi **living, versioned, evidence-backed school curriculum model**.

---

## 2. KSP Lifecycle

```text
DRAFT
→ REVIEW
→ APPROVED
→ LOCKED
→ SUPERSEDED
```

Revisi substantif membuat versi baru.

---

## 3. KSP Modules

### 3.1 Analisis Karakteristik Satuan Pendidikan
Data:
- murid;
- guru/tenaga kependidikan;
- fasilitas;
- lingkungan sosial-budaya;
- konteks daerah;
- learning outcomes;
- Rapor Pendidikan (jika diinput/diintegrasikan);
- feedback murid/orang tua;
- partner ecosystem;
- strengths/needs.

Tools:
- SWOT;
- root cause;
- fishbone;
- issue/priorities registry.

### 3.2 Visi, Misi dan Tujuan
Menyimpan:
- official statement;
- version;
- alignment ke school values;
- alignment ke graduate profile;
- measurable objectives;
- evidence indicators.

### 3.3 Pengorganisasian Pembelajaran
Mendefinisikan:
- intrakurikuler;
- kokurikuler;
- ekstrakurikuler;
- subject-based;
- thematic;
- interdisciplinary;
- block;
- school-specific activities.

### 3.4 Perencanaan Pembelajaran Tingkat Sekolah
Menyimpan:
- ATP reference per subject;
- broad assessment plan;
- annual cocurricular themes;
- academic calendar link;
- learning resource priorities.

### 3.5 Evaluation & Improvement
Menyimpan:
- evaluation period;
- input evidence;
- findings;
- root causes;
- decision;
- improvement action;
- owner;
- due date;
- follow-up result.

## 5. KSP Output

System dapat menghasilkan:
- DOCX/PDF KSP;
- compliance appendix;
- curriculum structure appendix;
- annual calendar appendix;
- cocurricular overview;
- evaluation report.

Output dihasilkan dari database yang approved/locked.

---

## 6. Contextualization for WMVAA

KSP harus memungkinkan pencatatan:
- lokasi Papua Pegunungan;
- kondisi akses teknologi;
- karakteristik peserta didik;
- prioritas literasi/numerasi/digital;
- Adventist education values;
- school formation/service programs;
- local content.

Kekhasan sekolah harus dihubungkan ke tujuan, program dan evidence, bukan hanya paragraf naratif.

---

## 7. Data Lineage

Setiap section KSP menyimpan:
- source type;
- source record;
- author;
- reviewer;
- approved_by;
- revision;
- evidence links.

Contoh:
“Prioritas numerasi” dapat dirujuk ke data hasil asesmen sekolah dan keputusan rapat.
