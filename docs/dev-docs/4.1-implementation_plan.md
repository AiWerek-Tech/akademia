### Phase 2: Comprehensive Test Suite (Sections E–J)

Write a single large test file `tests/database/Milestone2AcceptanceTest.php` covering:

#### E. Teacher Tests (20 scenarios)
- CRUD, required fields, invalid email/date, duplicate NIP/NIK/employee_number.
- Fuzzy name → creates review only (no auto-merge).
- Unit assignment, multi-unit, profile completeness, verify, activate/deactivate.
- Stale revision rejected, unit isolation (SMP admin can't edit SMA), audit PII masking.
- Soft delete (no hard delete).

#### F. Duplicate Review & Merge (18 scenarios)
- Exact match (NIP/NIK/employee_number/email), fuzzy name, Soundex false positive, Levenshtein candidate.
- KEEP_SEPARATE, REVIEW_LATER, MERGE decisions.
- Canonical field selection, combined unit assignments, archived duplicate.
- Transaction rollback, repeated merge rejected, merge into inactive rejected.
- **No auto-merge** on name/Soundex/Levenshtein/phone.

#### G. Subject Tests (15 scenarios)
- CRUD, duplicate code, alias, duplicate alias, unit availability SMP/SMA.
- Category validation, report/teaching-load flags, optimistic locking.
- Unit isolation, no JP field.

#### H. Grade Tests (8 scenarios)
- Seed verification, phase D/E/F, edit, invalid unit access.
- Grade can't be moved between units, deactivation guard, seeder rerun safe.

#### I. Classroom Tests (19 scenarios)
- CRUD, period/unit required, grade must match unit, duplicate code per period+unit.
- Homeroom teacher must have unit access, room must match unit or shared.
- Optimistic locking, copy preview/apply, skip existing, optional homeroom copy.
- Transaction rollback, unit isolation.

#### J. Room Tests (12 scenarios)
- Unit-specific and shared rooms, validation (non-shared needs unit, capacity, duplicate code).
- Inactive room type rejected, facilities JSON validation, optimistic locking, unit isolation.
